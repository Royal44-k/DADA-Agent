# M2字段验证与M3路由讨论整理

来源：本任务中的需求与方案讨论。此文件是2026-09-13补充的设计笔记，早期地址/记忆实验原文件没有找到，因此不补造相关准确率。

## 工作分层

- M1：1.7B初判与置信门控，选择a–m分支或交给M3复判。
- M3：调用9B处理分支判别分歧，产出最终路由；“纠正”按固定标准答案比较前后结果。
- M2：针对分支中的字段填写进行校验与错误反馈；用户最初设计为失败反馈给模型，重试仍失败后升级更强API LLM。具体重试次数及升级条件以对应生产版本代码为准。

## M2基础方案

让模型同时填写字段值与依据。依据引用用户原文，代码检查其是否存在，再按字段类型验证转换、归一化及约束。依据存在只能证明“引用来自输入”，不能单独证明所填字段语义正确。

对省略、否定、第三人称、历史信息与当次输入冲突等情形，还需判断依据归属与当前意图。验证结果建议区分通过、失败和信息不足；信息不足应澄清，不能随意补值。

| 字段 | 可用代码验证 | 校验边界 |
| --- | --- | --- |
| 时间 | 依据定位；使用JioNLP等解析器转换；固定参考时刻、时区；核对日期、时间、周期和范围 | 解析器也可能歧义，需处理“下周”“周末”等约定 |
| 地址 | 依据定位；行政区划字典与上下级一致性；门牌、楼栋、单元提取；名称归一化；地址解析/地理编码候选比对 | 地名同名、简称、相对位置及缺失城市需上下文；地图不存在不等于用户幻觉 |
| 数值与单位 | 中文数字转换、单位归一化、上下界及算术复算 | 区分目标值与变化量、百分比与百分点 |
| 手机、邮箱、网址、编号 | 格式、长度、字符集及适用校验码；与依据中的号码一致 | 格式正确不代表真实存在或归属正确 |
| 枚举和开关 | 值域、允许状态迁移、动作与目标对象配对 | 否定和反问不能只靠关键词 |
| 提醒事由 | 保留动作、对象、数量、地点等关键槽位；核对实体/数字；原文片段或约束性重组 | 自由摘要等价性无法仅用字符串规则证明；复合任务可能需拆分 |
| 用户记忆 | 主体、谓词、对象、否定、时间和来源分别存储；实体/数值一致性；新增、替换、删除与既有状态核对 | 不应把他人事实、假设或短期状态自动写成用户长期记忆 |

## 音量/亮度已保留的方案

9B抽取：方向（调大/调小/不变）、幅度类型（模糊幅度/明确变化量/明确目标值/极值）、幅度数值、当前用户原文依据。

代码按明确数值优先的原则计算目标。只有用户未给数值时，才按语境使用大/中/小对应15/10/5。明确变化量是在当前状态上加减，明确目标值直接设定；同时检查方向一致性、0～100边界及依据。

`typed-full-v3.log`记录核心152例×3轮=456次，455次全部通过（99.78%）。单独的16条边界用例在自动与强制工具模式下，安全弃答均仅4/16；因此高核心通过率不意味着模糊请求处理完善。

早期设备调节实现与补丁存放在`experiments/early-fg-isolation/`，供历史比对。是否可用于当前生产版本需单独验证。

## M3候选改进方案（未在本次归档中实施）

1. 将路由裁决与业务参数填写分开，用更小的裁决结构降低工具面板长度。
2. 输出label、动作、对象及逐字依据，记录每次是否覆盖M1以及覆盖理由。
3. 对候选集约束先测Top-K召回率；若正确分支不在Top-K中，硬约束会阻止纠错。
4. 用原文定位、对象/动作一致性辅助校验，保留否定、上下文补全和信息不足状态。
5. 按混淆对评估是否允许覆盖；模型自报confidence不能直接当作校准概率。
6. ASR归一化同时保留原文和变换映射，防止凭归一化文本新增意图。
7. 任何覆盖策略都使用独立、审校后的测试集验证纠正、引错与最终准确率。

这些方案的优先级应结合后续标签审校和有状态复测重新评估，不能直接从旧标签错误计数推导生产决策。
