# 结果口径与历史结论修订

本说明于2026-09-13整理现存资产，不是一次新的服务器测试。

## M3“纠正M1”的统计含义

在同一批样本、同一标准答案下，比较M1初判和最终路由：

- M1错误、最终正确：记为纠正。
- M1正确、最终错误：记为引错。
- M1和最终都错误：记为未纠正，其中可能发生错误标签之间的改判。
- M1高置信直出错误：没有进入M3。

这些是相对于所选标签的统计，必须先确认标签和分支定义有效，才能解释为语义能力结论。

## 8月18日数据闭合

`results-m1-m3-rerun2-1300-20260818.jsonl` 共1300条，原标签口径下1191条正确、109条错误。进入M3的285条中：保持正确174条、纠正8条、引错74条、仍错误29条。另有6条M1直错。109 = 74 + 29 + 6。

8 − 74 = −66只对该轮原始标签口径成立。后续审校改变了部分标准答案，不能继续把该差值作为M3固有能力结论。

此前讨论以 `8/(8+74)` 衡量覆盖效果，只考虑正确性发生变化的样本；它遗漏了可能存在的“错→另一错误”改判，因此不是全部M3改判的完整成功率。应以逐条 `m3_changed` 与经独立确认的标准答案重新统计。

## 8月19日标签审校

现存审校文档对原失败109条提出73条标签修改，其中70条修改后与原模型最终输出一致；在假设另外1191条标签无误的条件下，复用旧输出可计算为1261/1300（97.00%）。它既不是重新调用模型的结果，也不是独立全库标注验收。

审校明确了分支定义：d包含记忆新增、删除、修改；j指哒哒产品能力/功能支持/使用方法查询，不应泛化为所有客观知识问题；l为再见，k为睡觉/晚安。某些早期HTML沿用的简写或标题较宽泛，阅读时应结合此处定义和原流程图。

## 8月20日有状态复测及重试

v2首次完整输出文件 `results-full-v2-1300.jsonl` 中1278条正确。两条基础设施路由失败各重试一次后，`results-full-v2-1300-final.jsonl` 中1280条正确（98.46%），普通分类错误未重试。

v3资产继续修订3条标签，并复用v2输出条件性计算1283/1300（98.69%）。没有找到新的v3模型运行结果，因此不将其描述为服务器实测准确率。

## 如何使用历史改进建议

单一裁决工具、Top-K候选约束、原文证据校验、覆盖阈值和轻量覆盖分类器等均属待验证方案，不能写成已经证明有效的修复。尤其不能仅因早期原标签下“74条引错”，就认定应禁用M3或将所有分歧自动退回M1。

后续比较应固定经过审校的数据、对话状态、代码/模型版本和重试口径，再用独立测试集评估；在本批失败集上反复修改提示词或标签所得成绩应按开发集结果解释。
