验收判定

  • 单次完全正确：Schema/代码校验通过，方向、幅度类型、幅度值、原文依据和最终目标值全部正确。
  • 依据正确：模型给出的依据经 NFKC、空白和标点归一化后，必须是当前用户原话的连续子串；不能引用注入的当前设备状态。
  • 稳定性：同一语义连续三轮的“方向+类型+值”完全一致；依据稳定性另按逐字片段一致计算。
  • 边界安全：歧义、查询、描述或冲突语句不调用执行工具，转为澄清或忽略。

2被测方案：条件化三段式参数

仍保持用户指定的三个顶层字段，但将幅度对象改为按类型判别的条件 Schema，避免 9B 在“模糊幅度”下输出 80、100 等数字。

方向 direction
  ├─ 调大
  ├─ 调小
  └─ 不变

幅度 magnitude
  ├─ 模糊幅度   → value 只能是：大 / 中 / 小
  ├─ 明确变化量 → value 只能是：0～100 整数
  ├─ 明确目标值 → value 只能是：0～100 整数
  └─ 极值       → value 只能是：0 / 100

依据 adjustment_evidence
  └─ 当前用户原话中的逐字连续片段
关键改进 第一版把“汉字枚举或整数”同时开放给所有幅度类型，9B 会生成“模糊幅度 + 100”。改进版把类型和值绑定为四个互斥分支，使非法组合在生成阶段就被约束。

代码目标值换算

幅度类型代码规则示例（当前 60）
模糊幅度大=15、中=10、小=5；按方向加减并截断到 0～100“再降低点” → 调小+小 → 55
明确变化量优先使用用户给出的整数，不使用默认步长“降低 12” → 48
明确目标值直接采用目标值；方向由目标值与当前值比较“设为一半” → 50，方向调小
极值最大/最亮=100；最小/最暗/静音/归零=0“把声音拉满” → 100
不变仅允许明确保持，统一为明确变化量+0；不能作为理解失败的默认值“音量别变” → 60

方向、类型和逐字依据均正确，仅“无程度词的默认中幅”发生一次随机漂移。这说明默认步长虽已非常稳定，但仍不能只靠单次 LLM 输出实现 100% 确定性。

建议的 M2 处理 代码识别到“模糊幅度”后，应结合可维护的程度词映射进行二次勾稽；无任何程度词时固定回落到“中”。若模型输出与代码识别冲突，回喂具体错误码再重试，而不是直接执行 75。

6安全边界：三段式方案的主要短板

16 条边界语句仅安全拒答 4 条，拒答率 25% 自动工具选择为 4 / 16，指定工具选择同样为 4 / 16。“指定工具”在当前 9B 调用实现中也不能替代业务上的强制决策；模型有时仍会返回文本而不调用工具。

为何“依据存在”仍不够

查询句、陈述句和冲突句的文字当然存在于用户原文，所以“依据是原文子串”只能证明模型没有凭空编造文字，不能证明这段文字表达了可执行意图。原文可追溯是必要条件，不是充分条件。

7建议的生产级代码验证闸门

隔离实现已加入下列确定性校验，187 条 Python 规则测试全部通过。任何一项不满足都不得操作设备。

  1. 严格字段与条件类型：只能有合法方向；模糊幅度只能是大/中/小；明确值只能是 0～100 整数；极值只能是 0 或 100。
  2. 逐字依据：归一化后必须是当前用户原话的连续子串，禁止引用系统注入的“当前值”。
  3. 方向—目标值勾稽：目标值大于当前值必须调大，小于必须调小，相等必须不变；代码自行计算，不信任模型结论。
  4. 不变约束：“不变+模糊幅度”非法；明确变化量为 0 时方向必须不变；非零变化量不能配不变。
  5. 极值勾稽：最大/最亮只能到 100，最小/最暗/静音只能到 0，再与当前值比较方向。
  6. 范围截断：所有最终目标值统一截断至 0～100；边界处保留用户方向语义，但执行值不越界。
if decision != "执行":
    return 澄清或忽略

8推荐上线架构

三段式参数应作为“参数抽取层”，而不是同时承担意图判断、消歧和执行。推荐在它前后各放一道确定性闸门。

① F 分支路由识别设备域，不代表已授权执行
② 决策闸门执行 / 澄清 / 忽略；冲突或缺方向一律澄清
③ 9B 三段式方向 + 条件幅度 + 逐字依据
④ M2 代码勾稽类型、依据、方向、当前值、目标值全校验
⑤ 纠错与升级错误码回喂，最多 2 次；仍失败交 API LLM
⑥ 设备执行只接收代码计算且通过验证的 0～100 目标值

决策闸门的推荐输出

decision: 执行 | 澄清 | 忽略
reason_evidence: 用户原文逐字片段

只有 decision=执行 时，才进入本报告验证的三段式参数抽取。
不要用 direction=不变 代替“我没理解”。

M2 回喂错误码建议

错误码触发条件回喂重点
E_EVIDENCE依据不是原文子串要求逐字重抽，不得改写
E_TYPE_VALUE类型和值不匹配模糊只能大中小；明确只能整数
E_DIRECTION_TARGET方向与当前/目标值冲突重新做数值比较
E_AMBIGUOUS无方向、二选一、仅查询或描述不得执行，向用户澄清
E_MULTI_ACTION同时提高再降低等多动作拆分或确认顺序，不得只取第一段
