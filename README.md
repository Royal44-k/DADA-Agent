# 哒哒 Agent 测试资产

本仓库汇总哒哒 Agent 初上线阶段的流程图、13 分支测试用例、缺陷报告，以及对 a 至 e 分支的交互日志根因分析。当前结论是：问候、天气和时间类能力基本可用；提醒、长期记忆、音量亮度控制和时效性闲聊存在阻断级或高优先级问题。

## 当前测试结论

| 分支 | 功能 | 当前状态 |
| --- | --- | --- |
| a | 新建提醒 | 失败，确认后未写库，相对时间会漂移 |
| b | 删除或修改提醒 | 失败，前置查询为空后仍可生成虚假成功回复 |
| c | 查询提醒 | 被 a 分支写库失败阻断；查询结果为空 |
| d | 新增删除修改记忆 | 失败，确认后未写库 |
| e | 查询记忆 | 被 d 分支写库失败阻断；检索关键词还存在语义丢失 |
| f | 调整音量 | 失败，无设备状态变化 |
| g | 调整亮度 | 失败，模糊调低后仍保持原值 |
| h | 查询天气 | 正常 |
| i | 再见 | 正常 |
| j | 产品功能查询 | 流程图标注仅有框架，需专项验证 |
| k | 晚安 | 正常 |
| l | 查询时间日历农历宜忌 | 正常；原流程图误标为 i |
| m | 闲聊及其他意图 | 时效性问题未调用联网 API，出现编造和事实歪曲 |

## 建议修复顺序

1. 实现统一的待确认事务状态机，先修复 a 和 d 的确认后提交。
2. 将工具失败设为终止态，禁止 b 分支在失败后生成成功话术。
3. 修复 e 分支的语义检索关键词，并补充断线重连后的记忆回归测试。
4. 完成 f 和 g 的设备命令下发、状态回读和模糊调节策略。
5. 为 m 分支增加时效性与可变事实门控，强制走联网 API，并要求来源与时间戳。

## 安全说明

仓库未包含测试页原始交互日志。测试过程中发现日志可能暴露服务 Token，因此这里只保留脱敏后的结构化证据。请先轮换已暴露凭据，再共享任何原始日志。
